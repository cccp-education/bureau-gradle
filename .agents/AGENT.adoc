== Architecture

bureau-gradle is the *learner entry point* CLI/Docker for the education.ccp
ecosystem. Surnom borough: *Saint-Denis* (ville de France, département 93).

Niveau DAG: N4 (utilitaire, open core OSS edition).

Three roles:

. **Create office** — scaffold the learner `office/` structure (cercle 2,
  data pure, AsciiDoc pivot, git repo). Absorbs WSM-1 scaffold-plugin scope.
. **Create items** — couteau suisse invoking OSS tools to produce content:
  capsule, plan (planner), vibecode (codebase), site (bakery), slides
  (slider), documents (document), diagrams (plantuml), etc.
. **Consume training** — interface for versioned pedagogical material
  (MaterialUpdateContract — git pull / fetch && checkout tag).

Diagnostics (verifyBoroughs, inferMetadata, validateApiSchema, info,
BoroughDef) are secondary tasks — validation of the created office.

== Open core

- *bureau-gradle* (OSS, cccp-education, Apache 2.0) = this borough
- *workspace-gradle* (private, cheroliv) = édition maison implementing
  FormationRuntimePort (LocalAdapter + CloudAdapter) for edster.cloud

bureau-gradle is consumed by workspace-gradle via `includeBuild`.

== LLM consumption

bureau-gradle does NOT implement its own LLM layer. It delegates to
codebase-gradle N1 via `includeBuild` (pattern SLD-8 US-8.1):
- `codebase.koog.llm.LlmProvider` (koog abstraction, suspend)
- `codebase.koog.llm.service.LlmBuildService` (Gradle BuildService bridge)
- `LlmProviderResolver` resolves provider from model name (Ollama local,
  Ollama cloud pool, Gemini, HuggingFace, Custom)

Multi-provider support: Ollama local (small test models), Ollama cloud
pool (gpt-oss:120b-cloud / gemma4:31b-cloud, rotation 11437-11465),
Gemini (GoogleAiGeminiChatModel), HuggingFace (langchain4j, TBD).
